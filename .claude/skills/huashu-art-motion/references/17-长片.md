# 长片：10–30 分钟（以 20 分钟为准）

SKILL.md「先判断任务」里「做一支 10 分钟以上的片子」走这一页。短片的规则全部照旧（镜头表、画风锁、六种做坏方式、门禁），这一页只讲**多出来的问题**：结构、节拍疲劳、渲染工程、分段验收。

先说清楚证据：门禁阈值和 07 号的正面经验都来自 45 秒到几分钟的片子，作者还没有表过态的 20 分钟成片。下面的结构和节拍建议是从短片规则推出来的起点，不是标定过的结论；做完一支长片，把作者的原话和改法写回这一页。

## 一、20 分钟不是 20 支 1 分钟

一张几百行的镜头表，人看不过来，lint 也只能逐行查；一支 3.6 万帧的片子单进程渲几个小时，中途崩一次就得全部重来；整片平均一个快动帧占比，会把一整章翻页 PPT 摊薄掉。所以长片拆成**章**：

| | 短片 | 20 分钟长片 |
|---|---|---|
| 分镜 | 一张镜头表 | 总纲（画风锁＋章节表）＋每章一张镜头表 |
| 一个例子贯穿 | 全片一个 | 每章一个贯穿物，全片再有一个母题从第一章走到最后一章 |
| 片段语法 | 最多 2 种 | 每章最多 2 种，全片最多 4 种，全部同一个 `theme` |
| 渲染 | `render.py` 整片或逐镜 | `long_film.py render` 逐镜并行、断点续渲 |
| 门禁 | 整片一个快动帧占比 | 整片＋每章各一个，每章都要过 0.035 |
| 审片 | 一位 | 至少两位，按章分工，外加一遍完整正常速度观看 |

## 二、结构：章怎么分

- **6–8 章，每章 2–4 分钟。** 短于 45 秒撑不起一个段落，长于 5 分钟观众会走神（lint 报黄）。
- **每章回答一个问题。** 总纲章节表写「这一章的问题」。写不出问题的那一章，就是在凑时长。
- **冷开场 ≤ 60 秒**：一个具体小场景，把全片的问题抛出来（短片「开头 3 秒」的规则放大一级）；片名可以在冷开场之后才出，也可以不出。
- **每章开头是一个小场景，结尾落在一个动作上并把观众交给下一章**：手把东西递出去、门关上、镜头拉远露出下一章要讲的那个东西。章与章之间不插「第二章」字卡，章名放进 mp4 的章节元数据和简介里（assemble 自动写）。
- **全片母题**：同一个物或人，从第一章走到最后一章，它的状态随章节变（一块积木→被拆开→被重新拼起来）。最后一章回到它身上收束，不收在金句卡上。
- **中段换气**：8–12 分钟左右放一章节奏明显不同的（换主做法、换景别、换贯穿物的状态），防止中段塌下去。

## 三、节拍疲劳：长片最常见的死法

短片的「每镜同一个动作」在长片里放大成「每章同一种节拍」。一支 20 分钟的片子，每章都是「调查桌横移 → 缓推 → 硬切」，单看每章都对，连着看就是同一章放了七遍。

- **相邻章换主做法**：片段语法（y2 调查桌、t3 图表…）、scenes 代码画、真实素材满幅，轮着来。lint 查连续三章主做法相同（报黄）。
- **换的是节拍，不是画风**。画风锁、色板全片不变；换的是语法、景别、镜头基调、剪辑密度。
- **剪辑密度随章变**：信息章平均镜长 3–4 秒，情绪章可以 5–6 秒，高潮章 2–3 秒。lint 的单镜 2–6 秒规则每章照查。
- **重音全片计数**：快推、砸入每章都按三分之一的上限查，但全片最重要的三五个揭晓要留给真正的转折，不要每章都砸满。

## 四、工程：`scripts/long_film.py`

```sh
L=<skill>/scripts/long_film.py
python3 $L init  <项目> --minutes 20 --chapters 7     # 总纲.md、章节/*.md、代码工程/（scripts/engine 的拷贝）
python3 $L lint  <项目> [--script-dir 文稿/]          # 每章 storyboard_lint（继承总纲的画风锁）＋跨章检查；红灯不许开渲
python3 $L plan  <项目>                               # 每一镜怎么出、缺什么、估渲染时间
python3 $L render <项目> -j 4                         # 逐镜并行；已渲好的跳过；源文件改过的重渲
python3 $L status <项目>                              # 进度条＋按实测速度估剩余时间
python3 $L assemble <项目> [--music 配乐.wav]          # 拼章（有本章口播就混进去）→ 拼整片，章节写进 mp4，出 章节.txt
python3 $L gate <项目>                                # film_gate 按章分段量
python3 $L deliver <项目>                             # deliver.py ＋ 章节表；交付目录里附 章节.txt
```

**做法列写成脚本认得的样子**（plan 会逐镜告诉你认没认出来）：

| 做法列 | 怎么出 |
|---|---|
| `y2 片段 镜03.json` | `render.py --spec`；spec 的 `duration` 必须等于镜长，宽高 fps 等于总纲的画幅（plan 不一致就报） |
| `scenes/kitchen.js` | `render.py --solo kitchen --from 0 --to <镜长>`；场景要登记进 `代码工程/eras.js`（或总纲 `场景表：<名>` 指定的 `eras_<名>.js`） |
| `scenes/kitchen.js@12.5` | 同一个场景从第 12.5 秒起。一个场景跨几镜时，每镜接着上一镜的时间往下写，否则每镜都从第 0 秒重播 |
| `素材 素材/采访.mp4@30` | 从第 30 秒起截镜长那么长，缩放补边到统一画幅、帧率 |
| 其它 | 自动渲不了：把成品放进 `镜/<章>/镜NN.mp4`（plan 会认），或者改成 spec 用 `MD.cover` 放图 |

**渲染预算**（2026-10-29 在 4 核云端容器上实测，1920×1080@30）：

| 场景复杂度 | 每帧（4 路并行时单路） | 20 分钟 3.6 万帧，4 路墙钟 |
|---|---|---|
| 轻（包豪斯、8bit、参数化片段） | 0.12–0.19 秒 | 约 20–30 分钟 |
| 中（波普、印象派） | 0.3 秒 | 约 45 分钟 |
| 重（后印象派笔触） | 单路 0.37 秒，并行更慢 | 1 小时以上 |

帧默认用 JPEG 0.95 从浏览器传出来（`render.py --jpeg`）：PNG 编码＋传输每帧要 120–200ms，JPEG 约 25ms，成片还要过一道 x264，同一段 SSIM 0.989，看不出差别。要无损就 `render --png`。实测速度记在 `渲染/速度.json`，plan 和 status 用它估时间。

**改一章只重渲改了的镜**：镜的输出比它的 spec／场景文件／`eras.js`／`engine.js` 新就跳过。改了 `engine.js` 会让所有 scenes 镜过期，这是对的：引擎变了画面可能就变了。中途崩了直接重跑 render，只补没渲完的（渲完才改名落盘，半截文件不会被当成渲好的）。

## 五、口播与音频

- **按章录口播**（总纲章节表加「口播」列，`口播/01.wav`）：重录一章不会让后面几章全部错位。assemble 把每章口播混进那一章，画面短于口播会提示截尾。
- 整片一条口播也行：`assemble --audio 口播.wav`，替换各章音轨。
- 配乐 `--music 配乐.wav`（循环垫底，默认 -18dB，`--music-db` 调）。正式片的配乐、混音按 05 号做。
- 有口播时，镜头表的时间段以口播实际时长为准；lint 会报章节合计和总纲时长差得多的章。

## 六、验收

1. **lint 全绿或黄灯有理由**，才开渲。
2. **抽帧对画风**：每章抽 3–5 帧排成一排，再把各章的排在一起看；哪一章像从别的片子里拿来的，按画风锁重做。
3. **gate 分章量**：`long_film.py gate`。整片快动帧占比、每章快动帧占比（`fast_ratio_worst_part`）、空画面、蓝紫底，任何一项红灯不交付。逐段表会告诉你是哪一章塌了。
4. **审片至少两位**，按章分工写进 `审片/<人>_<章>.md`；另外必须有人用正常速度从头到尾看一遍，专看章与章的接缝和中段（8–12 分钟）有没有塌。deliver 在长片只有一份审片记录时会写进事实段。
5. **deliver**：`long_film.py deliver`，交付目录里附 `章节.txt`（YouTube 简介里直接贴）。

## 七、踩过的坑

- **场景跨镜不写 `@起点`**：同一个 `scenes/x.js` 在三镜里各渲一遍，每镜都从第 0 秒开始，观众看到同一个动作重播三次。
- **Playwright 版本和本机 Chromium 不对**：`uv run --with playwright` 会拉最新版，找不到预装的浏览器、又下载不了（云端容器常见）。`render.py` 和 `qa.py` 现在会退回用 `$PLAYWRIGHT_BROWSERS_PATH` 里已有的 Chromium（`engine/launch.py`，打印一行 `[launch]`）；还不行就设 `CHROMIUM_EXECUTABLE=<浏览器路径>`，或 `LONG_FILM_PYTHON="uv run -q --with playwright==<本机版本> python"`。
- **分段门禁的边界**：段边界上的切点、跨段的静止段会被切成两半；按章节切（gate 默认读 `章节.json`）边界本来就是硬切，最准。
- **用 `-c copy` 循环拼的测试片时间戳会乱**，分段解码读出来的数不稳；测试长片要重新编码。
